# 0022. Administration interface: look, live progress, maintenance and source editing

- Status: Accepted (2026-11-15), the user's request ("the admin panel needs some work"; chosen: look and layout, live progress, manage sources, maintenance tools)
- Date: 2026-11-15

## Decisions

1. **Look and layout.** Cards, status badges, `<meter>` bars for per-source and per-file sizes, a sticky navigation bar, dark mode (from the browser setting) and a phone layout, all in the one stylesheet. No inline styles: the content security policy stays strict.
2. **Live progress** for a running operation: a `<progress>` bar, documents so far, speed, time left and elapsed time, updated once a second by one script file served from the admin listener (`/assets/admin.js`). The policy now allows `script-src 'self'` and `connect-src 'self'` (and still forbids inline scripts and `unsafe-*`; a test checks both). The script sets only `textContent` and attributes from the API's numbers, never markup. Connectors report how far they are through `Control.setProgress` (bytes of a dump, files, items); where the total is unknown the bar is indeterminate. Without JavaScript the page still shows the state at load time.
3. **Maintenance operations**: check, backup and remove-source join imports in the job manager (one operation at a time, under the same writer lock as the command line). Removal needs confirmation (the source's name typed, or `confirm=yes` in the API). Backups go only into a folder fixed in the configuration (`[admin] backup_dir`), never a path from the request. `check` reports progress and can be cancelled. **Rebuild and restore stay on the command line**: both replace files the running server has open, and doing that safely needs an index swap under a lock around the search pool, which is a separate piece of work.
4. **Source editing.** Sources (and only sources) can be added, edited, enabled, disabled and deleted from the interface. The server edits the configuration file it was started with (`--config`): it parses the file with the TOML library, changes the `[[source]]` tables through the document model (values are escaped by the library, never concatenated, so a value cannot add a table or setting; comments elsewhere survive), validates the resulting text as a whole exactly as at startup (syntax, every setting, every source's options), and only then writes it atomically, keeping the previous file as `FILE.bak`. The new list replaces the old one in a shared store, so imports and pages use it at once without a restart. The file is re-read for every edit, so edits made by hand in between are kept. It requires `admin.actions`, a signed-in session with the form token (or the bearer token on the API), and is refused when the server was started without `--config`.
5. **What it does not do**: edit server, admin, index or search settings (they need a restart and stay hand-edited); delete a source's documents when the source is deleted (removal is its own confirmed operation); edit TOML that defines sources in other forms (inline arrays), which it reports instead of rewriting.

## Risks accepted

The interface can now write one file and run long operations. Both sit behind the same sign-in, session token and `actions` switch as imports, the file is validated before it is touched, and a backup of the previous version is always kept.
